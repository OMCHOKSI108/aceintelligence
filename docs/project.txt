1. PROJECT OVERVIEW
================================================================================

IntelligenceJobs is a full-stack job recruitment platform that connects
employers (admins) with job seekers (candidates). It features job posting,
candidate management, resume processing with AI-powered text extraction,
application tracking, interview scheduling, and employee onboarding.

Repository: https://github.com/OMCHOKSI108/intelligencejobs.git
Monorepo Structure: jobserver/ (backend) + jobclient/ (frontend)

4. DATABASE SCHEMA
================================================================================

4.1 Tables
----------

  USERS (users)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── loginId         VARCHAR UNIQUE NOT NULL (format: ADM-XXXX, EMP-XXXX)
  ├── email           VARCHAR UNIQUE NOT NULL

  ├── bio             TEXT NULLABLE

  ├── updatedAt       TIMESTAMP

  CANDIDATES (candidates)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── email           VARCHAR UNIQUE NOT NULL
  ├── passwordHash    VARCHAR NOT NULL (bcrypt, 10 salt rounds)
  ├── name            VARCHAR NOT NULL
  ├── phone           VARCHAR NULLABLE
  ├── verified        BOOLEAN DEFAULT false
  ├── verifyToken     VARCHAR NULLABLE
  ├── createdAt       TIMESTAMP
  └── updatedAt       TIMESTAMP

  JOBS (jobs)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── jobId           VARCHAR UNIQUE NOT NULL (format: JOB-XXXX)
  ├── title           VARCHAR NOT NULL
  ├── description     TEXT NOT NULL
  ├── hiringOrganization VARCHAR NOT NULL
  ├── location        VARCHAR NOT NULL
  ├── remote          BOOLEAN DEFAULT false
  ├── datePosted      TIMESTAMP DEFAULT NOW
  ├── baseSalary      INTEGER NULLABLE
  ├── employmentType  ENUM NOT NULL (FULL_TIME | PART_TIME | CONTRACT | INTERNSHIP | TEMPORARY)
  ├── validThrough    TIMESTAMP NULLABLE
  ├── jobBenefits     TEXT NULLABLE
  ├── experienceRequired VARCHAR NULLABLE
  ├── educationRequired  VARCHAR NULLABLE
  ├── skills          TEXT NULLABLE
  ├── status          ENUM DEFAULT 'draft' (draft | published | closed | expired)
  ├── createdBy       UUID NOT NULL (FK -> users.id)
  ├── createdAt       TIMESTAMP
  └── updatedAt       TIMESTAMP

  APPLICATIONS (applications)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── name            VARCHAR NOT NULL
  ├── email           VARCHAR NOT NULL
  ├── phone           VARCHAR NOT NULL
  ├── jobId           UUID NOT NULL
  ├── stage           ENUM DEFAULT 'RECRUITER_PHASE'
  │                    (RECRUITER_PHASE | ON_HOLD | SHORTLISTED | REJECTED | SELECTED)
  ├── appliedAt       TIMESTAMP DEFAULT NOW
  ├── createdAt       TIMESTAMP
  └── updatedAt       TIMESTAMP

  INTERVIEWS (interviews)
  ├── id              UUID PRIMARY KEY (auto-generated)

  ├── mode            ENUM NOT NULL (ONLINE | IN_PERSON)
  ├── location        VARCHAR NOT NULL (meeting link or physical address)
  ├── interviewerName VARCHAR NOT NULL
  ├── notes           TEXT NULLABLE
  ├── createdAt       TIMESTAMP
  └── updatedAt       TIMESTAMP

  RESUME_FILES (resume_files)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── applicationId   UUID NOT NULL
  ├── fileName        VARCHAR NOT NULL
  ├── mimeType        VARCHAR NOT NULL
  ├── size            INTEGER NOT NULL (max 5MB)
  ├── file            BLOB (long) NOT NULL (raw binary)
  └── createdAt       TIMESTAMP

  CANDIDATE_PROFILES (candidate_profiles)
  ├── id              UUID PRIMARY KEY (auto-generated)
  ├── resumeFileId    UUID NULLABLE (FK -> resume_files.id)
  ├── candidateId     UUID NULLABLE (FK -> candidates.id)
  ├── applicationId   UUID NULLABLE (FK -> applications.id)
  ├── uploadedBy      UUID NOT NULL (FK -> users.id)
  ├── fileName        VARCHAR NOT NULL
  ├── mimeType        VARCHAR NOT NULL
  ├── size            INTEGER NOT NULL
  ├── rawExtractedText TEXT NULLABLE
  ├── profileData     JSONB NULLABLE (structured resume data)
  ├── status          ENUM DEFAULT 'PENDING' (PENDING | PROCESSING | COMPLETED | FAILED)
  ├── processedAt     TIMESTAMP NULLABLE
  ├── errorMessage    TEXT NULLABLE
  ├── createdAt       TIMESTAMP

9. SECURITY
================================================================================

9.1 Authentication
--------------------
  - JWT tokens with configurable expiry (default: 7 days)
  - Password hashing: bcryptjs with 10 salt rounds
  - Token payload: { userId, role }

9.2 Rate Limiting
-------------------
  Login:          5 attempts per 15 minutes per IP
  Registration:   3 accounts per hour per IP
  Password change: 3 attempts per hour per user
  General API:    100 requests per minute per IP

9.3 Account Lockout
---------------------
  Max failed attempts: 5
  Lockout duration: 30 minutes
  Tracking: In-memory Map (resets on server restart)

9.4 Input Sanitization
------------------------
  - XSS prevention: strips <>, javascript:, on* event handlers, style=
  - Password validation: min 8 chars, uppercase, lowercase, number
  - Email validation: regex pattern matching
  - GraphQL query depth limit: max 10 levels
  - Body parser limit: 1MB

9.5 HTTP Security Headers (Helmet)
------------------------------------
  - Content Security Policy: disabled (development)
  - Cross-Origin Embedder Policy: disabled
  - Cross-Origin Resource Policy: cross-origin
  - Referrer Policy: strict-origin-when-cross-origin
  - HSTS: enabled in production (1 year, includeSubDomains)

9.6 CORS
-----------
  Allowed origins: configurable via CLIENT_URL env var
  Credentials: enabled
  Methods: GET, POST
  Headers: Content-Type, Authorization
  Max age: 86400 seconds (24 hours)

9.7 Error Handling
--------------------
  - safeError(): blocks internal error messages (DB, JWT, SQL keywords)
  - Production introspection: disabled
  - Audit logging for security events

10. FILE PROCESSING
================================================================================

10.1 Resume Upload Pipeline
-----------------------------
  1. File received (multipart/form-data, max 5MB)
  2. JWT verification + role check
  3. Filename sanitized (path traversal prevention)
  4. ResumeFile record created (raw binary stored in PostgreSQL BLOB)
  5. CandidateProfile record created (status: PENDING)
  6. Background processing triggered (fire-and-forget)

10.2 Text Extraction
----------------------
  PDF:     pdf-parse (text extraction)
  DOCX:    mammoth (raw text extraction)
  Images:  tesseract.js OCR (English language)

10.3 Resume Parsing
---------------------
  Raw text -> structured JSON:
    - Name, email, phone, summary
    - Skills array
    - Experience (title, company, duration, description)
    - Education (degree, institution, year)
    - Certifications array
    - Projects (name, description, url)
    - LinkedIn, GitHub profiles

10.4 Allowed File Types
-------------------------
  application/pdf
  application/msword
  application/vnd.openxmlformats-officedocument.wordprocessingml.document
  image/jpeg
  image/jpg
  image/png

19. KEY DESIGN DECISIONS
================================================================================

  - GraphQL-first API: Most operations via GraphQL, REST only for file uploads
  - Separate User/Candidate models: Internal staff vs external candidates
  - Role hierarchy: SUPER_ADMIN > ADMIN > EMPLOYEE (higher roles inherit permissions)
  - Soft deletes: User model uses paranoid mode (deletedAt)
  - File storage in DB: Resume files stored as BLOB in PostgreSQL (not S3)
  - Async resume processing: Fire-and-forget background processing
  - Dual email systems: Resend for candidates, Gmail for internal comms
  - In-memory rate limiting: Account lockout resets on server restart
  - No pub/sub or real-time: Request/response only
  - No caching layer: Direct PostgreSQL queries
